# Raspiaudio Muse Luxe Voice Satellite

ESPHome firmware that turns the [Raspiaudio Muse
Luxe](https://raspiaudio.com/produit/muse-luxe/) into a Home Assistant voice
satellite. It follows the behaviour of the [Home Assistant Voice
PE](https://github.com/esphome/home-assistant-voice-pe) firmware, on the Luxe's
hardware and through its considerably better speakers — with one unavoidable
difference, described under [One bus, shared](#one-bus-shared).

Built against **ESPHome 2026.9.0**.

This is a fork of [RASPIAUDIO/esphomeLuxe](https://github.com/RASPIAUDIO/esphomeLuxe),
rewritten against current ESPHome. See [What changed](#what-changed-from-upstream).

## What it does

- **On-device wake words** — `okay nabu`, `hey jarvis` and `hey mycroft`, with a
  sensitivity selector exposed to Home Assistant.
- **Voice timers** — timers set by voice ring on the device, and are silenced with
  the wake word or the centre button.
- **Announcements duck music** rather than cutting it off, because both streams go
  through a mixer into one output.
- **Media playback** from Music Assistant, Media Browser and anything else Home
  Assistant can stream, in FLAC.
- **Synchronised multi-room playback** with Music Assistant over Sendspin, so the
  Luxe can play in step with other speakers.
- **Battery level** reported to Home Assistant, and headphone-jack detection that
  switches the codec between the internal amplifier and the jack.

## Installing

Firmware images are attached to each
[release](https://github.com/mojansch/esphomeLuxe/releases).

### First time, over USB

Download `muse-luxe.factory.bin` from the latest release, put the Luxe into
download mode, and write the whole flash:

```bash
pip install esptool
esptool --chip esp32 --port /dev/ttyUSB0 write-flash 0x0 muse-luxe.factory.bin
```

Then give it Wi-Fi credentials, either over the serial port (ESPHome's Improv
support is built in) or through the access point the device brings up when it has
no network:

- **SSID**: `Raspiaudio-luxe`
- **Password**: `12345678`

Connect to it and open `192.168.4.1`.

Home Assistant discovers the device once it is on the network. The API encryption
key is generated by Home Assistant when you adopt the device, so there is no key
to copy by hand.

### Afterwards

The device polls `manifest_update.json` in this repository and exposes a
**Firmware** update entity in Home Assistant, so later releases install
themselves from there.

> **Updating from a release before 2026.9.2 needs one USB reflash.** From 2026.9.2
> the SPI bus runs at 80MHz instead of 40MHz, which is what lets an announcement
> play over music without crackling. That clock is set by the bootloader, and an
> over-the-air update only replaces the app partition — so a device updated over
> the air keeps running at 40MHz. It is perfectly safe, it just does not get the
> benefit until `muse-luxe.factory.bin` is written over USB once.

To flash your own build directly instead:

```bash
pip install esphome
esphome run muse-luxe.yaml
```

## Interface

### LED

The single LED on top shows one thing at a time, in this order of priority:

| Colour | Meaning |
| --- | --- |
| Purple, slow pulse | Starting up |
| Orange, slow pulse | No Wi-Fi or no Home Assistant connection |
| Orange, fast pulse | A timer is ringing |
| Dim red, steady | Microphone muted |
| Red, pulsing | Error |
| Blue, steady | Idle, listening for a wake word |
| Green, steady | Triggered, waiting for you to speak |
| Green, pulsing | You are speaking |
| Blue, fast pulse | Thinking |
| Yellow, steady | Replying |
| Amber, steady | Playing media |

### Buttons

| Button | Action |
| --- | --- |
| Plus | Volume up (hold to keep stepping) |
| Minus | Volume down (hold to keep stepping) |
| Centre, single press | Stop the timer, the reply or the announcement that is playing; pause music; otherwise start the assistant |
| Centre, double press | Mute or unmute the microphone |
| Centre, long press | Play/pause the media player |

## Music Assistant

Earlier versions of this firmware only decoded WAV, so the Music Assistant player
had to be forced to stream `.wav`. That is no longer the case — the device
advertises FLAC and Music Assistant will use it. If you set the output codec to
`.wav` previously, set it back to the default.

## Building

```bash
pip install esphome
esphome compile muse-luxe.yaml
```

`muse-luxe.yaml` pulls the codec component from this repository over Git, so a
plain compile works from a fresh checkout. To build against local edits to the
component, point `external_components` at the working copy instead:

```yaml
external_components:
  - source:
      type: local
      path: components
    components: [es8388_luxe]
```

### Known limitations

| | |
| --- | --- |
| No barge-in, no "stop" word | Shared I2S bus; see [One bus, shared](#one-bus-shared). Tracked upstream in [#16882](https://github.com/esphome/esphome/pull/16882). |
| Announcements lag a Voice PE by ~0.5s | HTTP connect to Home Assistant's transcoding proxy plus decoder start. An ESP32 will not win this against an ESP32-S3. |
| Headphone jack routing is untested | The codec switches routes on jack detect, but nobody has listened to it. |

### Equalisation

There is none in the firmware. Use Music Assistant's DSP if you want it — that is
where the parametric EQ lives, and it works.

Worth knowing for anyone who wants to change that: the ES8388 has an undocumented
hardware shelving filter (a 30-bit `Shelving_a` across registers 30–33 and
`Shelving_b` across 34–37). The datasheet names the registers but gives no
transfer function, so using it means deriving the topology by measurement.
Alternatively `art_biquad.h` from `esp-audio-libs` is already linked into the
build, so a filtering virtual speaker in the style of `mixer` and `resampler`
would slot into the chain. Neither is done here.

### Why a custom codec component

ESPHome ships an `es8388` audio DAC, but it targets ESP32-LyraT style boards: it
never powers up the analogue output stage, and it turns on the codec's automatic
level control, which fights the microphone boost the Luxe needs. `es8388_luxe`
keeps the register sequence that suits this board while implementing ESPHome's
standard `audio_dac` interface, so volume and mute are done in the codec instead
of by scaling samples in software.

## Releasing

1. Bump `esphome.project.version` in `muse-luxe.yaml`.
2. Run `tools/release.sh`.
3. Commit and push the updated `manifest_update.json`.

The script builds, refuses to publish an image that no longer fits the app
partition, creates the GitHub release with both images attached, and writes the
version and checksum into the manifest. `tools/release.sh --dry-run` builds and
reports the size without publishing.

Flash and PSRAM share one SPI controller on this chip, and the build runs both at
80MHz. Mixing two decoded audio streams here is bandwidth bound rather than CPU
bound, so that clock is the difference between clean announcements over music and
audible crackle. Since the bootloader owns the setting, changing it only takes
effect through a USB flash.

The app partition is 0x1F0000 bytes and the build uses most of it. **Do not change
the partition table**: an over-the-air update writes into the layout the device
was flashed with, so a device already in the field would no longer be able to
update itself.

## What changed from upstream

The upstream configuration targeted ESPHome 2025.2 and had drifted:

- **The two speakers were configured to cancel each other.** The codec driver set
  `DAC_invR` (DAC Control 6, bit 4), which puts the right channel 180 degrees out
  of phase, together with the mono mix in DAC Control 7. Two identical signals in
  opposite polarity cancel: no bass, a dead spot directly in front of the
  speaker, and both drivers together quieter than either one alone. The same
  write clobbered `ClickFree`, which is meant to be on. Those registers are now
  left at their defaults. This was latent upstream too — the writes lived in the
  jack-detect script, which only runs when a headphone plug is inserted or
  removed, so a device that never saw one escaped it.
- There was **no media pipeline**, so everything went through the announcement
  pipeline in WAV. That is why the old README told you to force Music Assistant
  to `.wav`: WAV was the only codec compiled in.
- The `okay_nabu` wake word was **loaded twice**, and the sensitivity selector
  only adjusted the second copy.
- Volume was reimplemented in globals that never tracked the media player's own
  restored volume, so the first press after a reboot, or after a change made from
  Home Assistant, jumped.
- `num_channels` on the I2S speaker was silently discarded — it is derived from
  `channel:` now, which defaults to mono. The Luxe is a stereo cabinet, so this
  sets `channel: stereo` explicitly.
- Two `platformio_options` were Arduino-only and ignored by the esp-idf build.

The rewrite moves to the current ESPHome audio stack — a mixer and two resamplers
feeding one output, with separate announcement and media pipelines and a
`speaker_source` media player — which is what makes ducking, timers and FLAC
streaming possible.

### One bus, shared

The microphone and the speaker hang off a single I2S peripheral, and ESPHome's
`i2s_audio` bus allows one direction at a time. Wake word detection therefore has
to release the bus before anything can play, and take it back afterwards. That is
what `release_bus_for_playback` and `reclaim_bus_for_microphone` do.

The visible consequence is that this device cannot detect a wake word while it is
talking, so there is no barging in on a reply and no "stop" wake word. Use the
centre button instead.

This is an ESPHome limitation rather than a hardware one, which is worth stating
precisely because it is fixable. ESP-IDF allocates a transmit and a receive
channel on one I2S port in a single call, and the Luxe is wired for exactly that:
shared BCLK, LRCLK and MCLK with separate data lines into and out of a
full-duplex codec. ESPHome's `i2s_audio` just does not use it that way - the
microphone and the speaker each allocate their own channel, so a mutex has to
keep them apart.

[esphome/esphome#16882](https://github.com/esphome/esphome/pull/16882) implements
full duplex for shared-bus voice assistants, including a resampler microphone
platform for the case here where the microphone runs at 16kHz and the speaker at
48kHz. It is not merged: no reviews since June 2026, and at least one user
reports it broken on 2026.9.0, the version this firmware targets. Worth watching
rather than adopting. If it lands, barge-in and the stop word become possible and
the whole bus hand-off below can be deleted, along with the latency it costs.
